# Mode B · 交付格式與五封範本

> 這份管五封信的**長相**：寄出節奏、主旨、第 2–5 封骨架，以及每跑一個人要交出的那份文件。
> 流程、判斷與外洩防線在 `sequence-5touch.md`；頁尾在 `email-format.md`。
> 正文仍受《內文風格指南》業務信件一節與《禁用詞清單》類別 X 管轄。
> `<your-…>` 與 `<業務姓名>` 是佔位符，執行時替換成真實值。

---

## 一、交付文件格式（每人一份）

每跑一位收件人，交出一份文件，版面照下面這個順序，**不要增減區塊**：

```
{姓名} · 陌開五封信
{建立日 YYYY-MM-DD} 建立　·　五封 Gmail 草稿皆已就緒，尚未寄出

── 收件人 ──
| 項目 | 內容 |
| 姓名 | {姓名} |
| Email | {email} |
| 電話 | {電話} |
| 名單 | #{列號} · {分層} · 付費 {金額} · 參與 {場次} 場 |
| 職業 | {職業} → 切角「{sequence-5touch 步驟 2 切角表那一組}」 |
| AI 類型 | {AI類型} |
| 認領人 | {認領人帳號}（{認領日} 認領） |
| 接觸狀態 | 已聯絡，待回覆（Remark 已註明「尚未寄出」） |

── 三個時段（來源：行事曆 Available 扣掉既有會議）──
| 時段 | 備註 |
| {M/D（週）HH:MM–HH:MM} | {整段乾淨／被哪場會議壓掉多少} |
| ×3 |

── 第 N 封　·　寄出日 {YYYY-MM-DD（週X）} ──（×5）
| 主旨 | 這封在做什麼 | ask |
| {主旨} | {一句說明} | 高／低／零 |
內文
{正文 ＋ 頁尾}

── 寄出前要處理的事 ──
（固定清單，見第四節）
```

「這封在做什麼」與 ask 欄照第二節的表抄，那是給寫信的人跟主管對照階梯用的。
這份文件含收件人個資，**存在內部 Drive，不要放進任何 repo**。

## 二、節奏

**三天一封，第 1 封一律禮拜二寄**（禮拜二開信率最高）。
寄出日是 **T、T+3、T+6、T+9、T+12** → 星期 **二、五、一、四、日**。

| # | 寄出日 | 主旨 | 這封在做什麼 | ask |
|---|---|---|---|---|
| 1 | T（二） | 我想邀請你一起發想 AI 應用痛點 from 彼得的外商隨筆 | 客製開場 ＋ 痛點問句 ＋ 30 分鐘 ＋ 三時段 ＋ LINE | 高 |
| 2 | T+3（五） | 聚焦你的 AI 應用需求 | 把問題變選擇題，回一個數字就好 | 低 |
| 3 | T+6（一） | 之前講得太抽象？這裡分享一個實際案例 | 給一條流程的實際長相（依職位選） | 低 |
| 4 | T+9（四） | 你知道沒有預算也沒有關係嗎？ | 純給、零 ask：政府補助三個判斷點 | 零 |
| 5 | T+12（日） | 最後一封信，之後不再打擾 | Breakup，留退出鍵 | 零 |

時段只出現在第 1 封，**三格都落在 T+2 到 T+8 之間**。第 2–5 封不列時段、不寫「今晚」「今天下午」。

> 第 5 封主旨 2026-09-30 審稿時換掉，舊版是「最後一次機會，錯過之後將失去免費的諮詢服務」。
> 它的催促感跟 Breakup 的方向相反，可能拉高被檢舉率，而且免費諮詢其實不會過期。
> 主旨要跟正文同一個方向：放手、留退出鍵。不要改回催促型主旨。

## 三、五封骨架

`{名}` = 名字不含姓（王小明 → 小明）。`{…}` 是要依人替換的地方，其餘照抄。
稱呼：第 1 封 `Hi {名}，`、第 2 封 `哈囉{名}，`、第 3–5 封 `{名}，`。對學員全程用「你」。

### 第 1 封 · ask 高

**正文照 `sequence-5touch.md`「第 1 封骨架（寄件人手改定稿）」**，這裡不重寫一份，避免兩處分叉。
主旨用第二節的第 1 封主旨；頁尾帶資訊區塊＋完整簽名檔（`email-format.md`）。

### 第 2 封 · ask 低

```
哈囉{名}，

上次提到的問題範圍有點廣，想說稍微聚焦一下。

你這禮拜花最多時間人工處理的是哪一件？回一個數字就好：
1. {選項 1}
2. {選項 2}
3. {選項 3}
4. {選項 4}

免費諮詢的名額還空著，想聊的話回我們一句時間就可以。

<業務姓名>
Zynkr 業務與顧問
<your-sales-account>
```

四個選項依職位切角寫，每個都是那個職位**這禮拜真的會遇到的一個畫面**。

| 切角 | 四個選項範例 |
|---|---|
| 專案／產品 | 同一份資料在幾個系統各有一份，不確定哪份說了算 · 客戶回報的問題轉到其他部門就變了樣 · 追進度靠一個個問，問完還要自己彙整 · 交接時誰承諾過什麼，事後找不到出處 |
| 事務執行 | 同一份資料要在好幾個表單或系統之間重打一次 · 報名表、問卷收回來還要一筆筆整理成表格 · 各部門交來的東西格式都不一樣，要先統一才能用 · 同事來問「那份資料在哪」，要翻好幾個地方才找得到 |

### 第 3 封 · ask 低

```
{名}，

也許用提問的方式有點抽象，想說直接給你看成品。

{一句他那個職位的處境}

{流程長相，寫成一段散文，步驟一步都不能少}

{這條流程的記憶點}

{對他的好處，一句}

還有興趣想了解的話跟我們說，回「有興趣」就好。

<業務姓名>
Zynkr 業務與顧問
<your-sales-account>
```

流程一律取自 `sequence-5touch.md` 步驟 3「職位 → 流程對照」表，**不要自己編步驟，也不要畫 `↓` 流程圖**
（列點只准留給第 1 封的三件事與時段）。專案／產品的範例（客訴轉 issue）：

> 平常追跨部門的進度回報，專案經理最容易當夾心餅乾，跟進非常困難。
>
> 換成有 AI 的流程會是這樣：客戶在對話裡回報問題，AI 先讀那段零散的描述，抽出版本、裝置、操作順序和錯誤訊息。接著比對現有的 issue 清單和知識庫，已知的問題直接回現成解法，不另開工單；新問題才交給客服判定是不是 bug、嚴重度多少。判定完才建 issue，工單編號和 issue 編號雙向連結。
>
> 最要緊的是客服判定那一步。是不是 bug、嚴重到什麼程度，牽涉客戶關係跟商務承諾，必須留給人判斷，AI 只負責把材料準備好。
>
> 研發收到的單子會從「客戶說不能用」變成「在 X 版本點 Y 會出現 Z」，你就不用當那個中間翻譯的人。

事務執行的範例（名單解析與分級）：

> 活動報名、官網表單、廣告名單，收回來的資料常常一半是對方自己打的一段話。整理這些的人，通常就是行政。
>
> 換成有 AI 的流程會是這樣：名單一送出，先用規則把 Email 和公司統編的格式整理好，再跟既有客戶比對，重複的就不另建。接著 AI 讀對方自己打的那段文字，抽出產業、規模、用途和急迫度，寫成一段摘要。條件符不符合，由事先定好的規則判斷；缺資料或不符合的，交給人決定要不要留。最後寫進客戶名單，業務打開就知道這通電話該講什麼。
>
> 最要緊的是失敗的那一筆。AI 讀不懂的時候，名單照樣建起來，標上「待人工補」，放進每天要看的清單裡。對方填的原文也永遠留著，AI 不改。
>
> 你要做的會從「一筆筆重打」變成「看被標出來的那幾筆」。

### 第 4 封 · ask 零

```
{名}，

想另外提一件事：如果卡的是預算，我們這邊也許幫得上忙。

常有客戶跟我們說「可是我們沒有預算」，但滿多時候公司是可以申請政府補助的。我們有合作的政策資源顧問，這裡先給你三個簡單的判斷點，看看有沒有機會：
1. 補助是核銷性質：公司要先把錢花出去，例如講師費、系統費用，才能拿單據向政府請款。
2. 申請的一定是公司本身，個人不行，也不是由我們代為申請。
3. 要講得出公司想解決的一個具體問題。只寫「導入 AI 增加營收」幾乎不會過，因為每家公司都想增加營收。

時間上，每年上半年是公告和受理期，9 月以後多半已經在準備明年的案子。

{依職位的一句，見下表}

這封不用特別回信，只是想提供一些參考資訊，希望幫得上忙。

<業務姓名>
Zynkr 業務與顧問
<your-sales-account>
```

| 切角 | `{依職位的一句}` |
|---|---|
| 決策層 | 刪掉這句，他就是決定的人 |
| 業務／專案 | 你很可能就是被問「這能不能報補助」的那個人，先知道這三點就夠用了。 |
| 事務執行／工程 | 這件事通常不是你自己決定。如果你們公司有人在看補助，這封可以直接轉給他。 |
| 一人規模 | 第 2 點要老實講：個人不能申請。改寫成別的純給內容，不要硬塞補助 |

三個判斷點只能來自補助內部文件「運作機制」一節的一般制度事實；合作方、收費、分潤的任何資訊都不得進信（`sequence-5touch.md` 步驟 4）。

## 四、寄出前要處理的事（交付文件最後一節，照抄後改日期）

```
· 第 2–5 封的主旨要先刪掉【M/D 寄】標記，那是排程用的，不是給收件人看的
· 建議開已寄出的第 1 封按「回覆」，再把草稿內容貼過去送出，收件人才會看到摺疊成一串的 thread，被判成群發的機率最低
· 寄出日是 {T}（二）、{T+3}（五）、{T+6}（一）、{T+9}（四）、{T+12}（日）；第 1 封延後寄的話，五個日期整串往後推，時段重查
· 第 1 封寄出後，把接觸紀錄 Remark 結尾的「※ 尚未寄出」拿掉
· 五封就停。沒回的把狀態改「暫時沒需求」，半年後換由頭再說
```
